# LUMAVUN Hedge Bot v0.3
Standalone Android project in android-hedge. Desktop terminal is unchanged. No NEXUS login, WebView, Vercel, MT5 or desktop backend in the APK.
- Settings -> Sambungkan API Exness: input account ID, API key, signing key (64/128 hex or PKCS#8 PEM), Gateway copied from Exness DNS widget. A signed discovery/account/snapshot test must pass before storing credentials. AES-GCM via Android Keystore encrypts local credentials; do not paste credentials into GitHub or chat. Exness platform API eligibility and scope still apply.
- Home: direct broker snapshot (balance, equity, used margin, currency, open position direction/volume). Equity minus balance is a difference, not verified per-position floating PnL. Snapshot expires after 30 seconds and on backgrounding.
- History: on demand, first page of close deals for last 24 hours, raw broker-reported profit amount/currency, filter by sign. Does not sum net realized PnL, reconcile commission/swap or paginate. API may reject this range; limits response is fetched but its dynamic window is not yet applied. 
- ExnessClient.java includes signed REST transport, openPosition/closePosition/operation primitives; these are not called by the UI. Execution is LOCKED. Need live ticks, instrument conditions, actual margin checks, persistent idempotency and operation reconciliation, bot-owned position tracking and demo account tests before enabling auto trading. No foreground service/cloud worker. Never enable real orders just because an HTTP ACK succeeds.
- References: https://www.exness-api.com/authentication/request-signing ; https://www.exness-api.com/trading/get-started/access-point-host-discovery ; https://www.exness-api.com/reference/trading/get-trading-state-snapshot ; https://www.exness-api.com/reference/get-deals-history ; https://www.exness-api.com/reference/open-position ; https://www.exness-api.com/reference/close-position ; https://www.exness-api.com/reference/trading/get-operation-status .
- Existing isolated JS hedge decision tests: node --test hedge-bot/hedge.check.mjs. Build: gradle -p android-hedge :app:assembleDebug (JDK 17, Gradle 8.9, SDK 35). No live broker credentials used for CI.

## Android permanent update signing (v0.4.2+)
Distribution uses only the release APK artifact `LUMAVUN-Hedge-signed`. Release applicationId stays `com.lumavun.hedge`; local debug uses `com.lumavun.hedge.debug` so development builds cannot collide with release installs. Increase versionCode for every release. Do not distribute debug or unsigned builds.

Repository administrator: add the private signing bundle as an Actions repository secret named `LUMAVUN_ANDROID_SIGNING_BUNDLE`, using the supplied JSON (keystore_b64 and password). Keep an offline private backup. Never commit or expose the bundle, password, keystore, or API credentials. The key alias is `lumavun-hedge`; the release workflow pins its public certificate SHA-256 and checks APK signature, package ID, and version before upload. No secret or mismatched certificate means no signed artifact. Only the designated APK branch is allowed to sign. Protect the repo/branch and restrict workflow-writing access.

This is a one-time signing migration. Old GitHub Actions debug APKs used ephemeral signing certificates; their private signing key was not retained by the former workflow. A new certificate cannot update an installation with the old signer. Back up required account information securely, stop the bot, uninstall the old debug application once, and install the first signed release. Local app data and Android Keystore entries are removed on uninstall. Future signed releases use the same certificate and application ID and preserve app storage when installed as an update. Do not clear data or uninstall for ordinary signed releases. Actual on-device update verification is still required.
